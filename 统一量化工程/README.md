# 统一量化工程

- 目标: 将“加密量化MVP”“动态对冲返佣网格”“网格和回测可视化”“对冲网格MVP”整合为一个单一工程，形成前端统一、后端中台、策略与回测引擎三层架构。

- 架构分层:
  - 前端应用: 使用 `加密量化MVP` 的 React+Vite 前端作为统一 UI。
  - 后端中台: 使用 `网格和回测可视化` 的 FastAPI 作为统一 API/编排层（REST + WebSocket），负责回测任务调度、进度与结果落盘、K线数据服务。
  - 策略与回测引擎: 使用 `对冲网格MVP` 的网格/对冲策略与资金曲线逻辑，配合中台自研回测执行器（支持双向持仓/对冲模式）。

- 统一约定:
  - 结果输出路径: `网格和回测可视化/cache/last_result.json`
  - 数据目录: `网格和回测可视化/K线data/`（含重采样与缓存）
  - 接口协议: 见 `接口规范/回测结果.schema.json`

- 对接关系:
  - 前端从中台拉取 REST/WS 接口，替换原本本地文件读取或临时路由。
  - 中台直接编排自研回测执行器与网格/对冲策略库，统一写入 `cache/`。
  - 网格/对冲策略库由中台直接调用，作为分析插件，输出与 schema 对齐的 JSON。

- 后续改造清单（Phase 1）:
  - 在前端将回测结果来源切换为中台 REST。
  - 在中台标准化进度与结果写入，形成稳定 JSON。
  - 在策略库统一参数与数据路径，保证可重入的批量遍历。

- 路径映射: 见 `目录映射.md`

## 目录结构（中文分层）
- `apps/加密量化MVP`: 前端应用（React+Vite）
- `services/后端中台`: FastAPI 编排与数据服务（REST/WS、进度与缓存）
- `packages/共享协议`: 前后端共享类型与 JSON Schema 对齐
- `packages/策略库/网格对冲`: 网格/对冲策略与资金曲线模块（原对冲网格MVP）
- `data`: K线与缓存数据（不忽略，跨设备可直接拉取）
- `scripts`: 跨项目脚本（数据预处理、发布、迁移）
- `docs`: 说明与架构文档
